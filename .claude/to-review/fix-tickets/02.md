## What to build

The web To review side panel should look and work like the Add expense form, not a raw editor. Today it shows "Currency (e.g. INR)", "Date (YYYY-MM-DD)", lowercase values like "equal", and messages like "Who paid?.0.amount: Enter the amount…".

- **Same fields and pickers as Add expense:**
  - the panel reuses the form's amount, description, date, paid by, split and Tag pickers, plus its optional details;
  - no code-style labels or raw values.
- **Behaviour that stays the same:**
  - each change is kept against the current version as you go;
  - a newer version from elsewhere shows the "what changed and who" note;
  - Save expense saves exactly the version shown;
  - Save is disabled with a reason while details are missing, or while a possible duplicate isn't ticked;
  - Delete asks first.
- **Problems in member words:**
  - what's missing or wrong comes from the shared To review model's member wording, for example "Who paid?" or "The amount paid by Ankit Das?";
  - server validation messages with field paths are never shown raw;
  - any new wording is added to the shared model, so Android can reuse it.

## Acceptance criteria

- [ ] The panel uses the Add expense form's pickers for date, paid by, split and Tag. No "(e.g. INR)", "(YYYY-MM-DD)" or raw values like "equal" or "other" appear.
- [ ] Fixing a missing payer with the payer picker, and changing the date with the date picker, are both kept as you go, and the item moves to Ready.
- [ ] No field paths appear anywhere on the To review page. Problems use member words from the shared model.
- [ ] The existing To review behaviour still passes:
  - the "changed while you look" note;
  - the exact-version save;
  - the duplicate tick;
  - Delete confirmation;
  - the one-at-a-time run.
- [ ] Shared unit tests cover any new member wording in the four CI time zones.
- [ ] Playwright journeys on the demo seed cover the panel, in light and dark at 130% text, with axe passing.
