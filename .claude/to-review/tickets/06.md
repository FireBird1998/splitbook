## What to build

To review on Android, part 2: going through items one at a time. It starts from a Group's **Review one at a time**, or from Home's **Review N, one at a time** across every Group.

- **Header.** The Group name is the title, because saving into the wrong Group is the real risk. The subtitle reads "Review · 3 of 5 · across 2 Groups". A progress bar shows done, current and remaining. Close returns to where the run started.
- **Order.** The shared model's run order, Group by Group.
- **The card.**
  - Where it came from: "Prepared by Claude · from your chat · today 10:41", or "You set this aside · Finish later · yesterday 21:05".
  - The amount, the description, and tiles for date, paid by, split and Tag, opening the existing pickers.
  - The per-person split line.
  - Each change is kept straight away.
- **Missing details.** The missing tile is highlighted ("Who paid? · Choose"), with "One thing left before you can save: who paid", or "Claude didn't know who paid, so it left that to you". Save is disabled with the reason.
- **Possible duplicate.** The matching expense is shown, with "It's a different expense, save it anyway" to tick before Save works.
- **Changed while you look.** "Claude changed the amount a moment ago: ₹2,350.00 → ₹2,400.00. You're seeing the latest version."
- **Actions.** **Save expense** (saves the version on screen and moves on), **Delete** (sheet: "It was never saved, so nothing in <Group> changes. You can't undo this.") and **Skip for now** (leaves the item and moves on).
- **End of the run.** "Done for now", "You went through 5 items in Maple House and Goa Friends Trip", then Saved, Deleted and Left for later, then Done back to Home. Skipped items stay in To review.
- **Offline.** Account items in the run are read-only: "Connect to change or save this". The run can still be closed.

Design: the ReviewCard board, all states (needs details, ready, possible duplicate, changed by Claude, delete, end of run), and both "from" variants.

## Acceptance criteria

- [ ] The run follows the shared model's order and crosses Groups from Home, with the Group name always in the header.
- [ ] Changes are kept as you go. A newer version from someone else shows the "what changed and who" note.
- [ ] Save saves exactly the version on screen. It is disabled with a reason while details are missing or a possible duplicate isn't ticked.
- [ ] Delete asks first and is permanent. Skip for now leaves the item where it is.
- [ ] The end summary counts saved, deleted and left-for-later correctly.
- [ ] Offline, items are read-only with the message.
- [ ] Render tests through the mobile controller cover every state, at 130% text, in dark, and with a screen reader label on every control. The mobile HTTP verifier covers saving from the run.
