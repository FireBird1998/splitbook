## What to build

The web To review page for a Group, at `/groups/<id>/review`. It replaces the Drafts tab, and the old address redirects here.

- **Header and summary.** "Only you can see these. Nothing here changes Balances until you save it." A summary shows ready, needs details and possible duplicates, followed by **Save N ready** and **Review one at a time**.
- **The list.** Items are in sections: Ready, Check before saving, Needs details. Each row shows the description, the amount (exact, in the Group's currency), the date and where it came from ("From Claude", "You set this aside"). A needs-details row names what's missing ("Who paid?").
- **Side panel.** Clicking a row opens the item in the side panel, following the Expense side panel pattern.
  - Fix any field there; each change is kept straight away as the Draft's new version.
  - **Save expense** saves exactly the version on screen, and is disabled with a reason until the item is complete.
  - **Delete** asks first: "It was never saved, so nothing in <Group> changes. You can't undo this."
  - "Claude didn't know who paid, so it left that to you" appears where it applies.
- **Possible duplicate.** The panel shows the existing expense it resembles (description, date, amount, who added it). Save stays disabled until the member ticks "It's a different expense, save it anyway". Possible duplicates are never part of Save N ready.
- **Changed while you look.** If Claude (or the member on another device) changes the item while it's open, the panel refreshes to the latest version and says what changed and who changed it: "Claude changed the amount a moment ago: ₹2,350.00 → ₹2,400.00".
- **Save N ready.**
  - A confirmation dialog lists each item (description, date, payer, split, source), the exact total, and "They'll be added to <Group>, and Balances there will change for everyone".
  - Confirming saves exactly those versions.
  - A results view reports each item: saved, couldn't save (with the reason and a way to fix it), or "We didn't hear back, so it may already be saved" with **Check again**, which retries with the original identity and can never save twice.
- **Review one at a time.** Opens the first item in the panel with "1 of 5" and **Next** / **Skip for now**, in the shared model's run order. It ends with "Done for now · Saved 2 · Deleted 1 · 2 left for later".
- **Empty state.** "All caught up", with a way back to Expenses.
- **Leaving a Group.** The Leave Group confirmation adds: "You have 3 items in To review for <Group>. They're kept but hidden while you're not a member." This only appears when the count is above 0.

Design: the ReviewList and ReviewCard boards (phone), adapted to the web list and side panel.

## Acceptance criteria

- [ ] `/groups/<id>/review` shows the sections, rows and summary from the shared model, and the old Drafts tab address redirects to it.
- [ ] Each change in the panel is kept as you go. A stale version shows the latest one with a "what changed and who" note, and nothing is overwritten silently.
- [ ] Save expense saves exactly the version on screen. It is disabled with a reason until the item is complete, and for a possible duplicate until the box is ticked.
- [ ] The Save N ready confirmation lists exactly the ready items with an exact total, and confirming saves exactly those versions.
- [ ] Per-item results show saved, failed and "may already be saved". Check again never creates a second Expense: covered by an expense-access spec that loses the reply.
- [ ] Delete asks first and then removes the Draft permanently, and the ledger is unchanged.
- [ ] Review one at a time follows the run order and ends with the summary.
- [ ] The Leave Group confirmation shows the item count when there is one.
- [ ] Playwright journeys on the demo seed cover: fixing a missing payer, a possible-duplicate tick, Save N ready with mixed outcomes, Delete, the changed-while-open note, the one-at-a-time run, and the empty state. Axe passes in light and dark.
