## What to build

To review on Android, part 3: putting things aside, offline behaviour, and the last details.

- **Finish later in the Add expense form.** It replaces "Keep as Draft", with the help line "Keeps it in To review. Only you can see it." It creates a Draft prepared by the member and confirms with "Kept in To review · View". At the limit it is disabled with the per-member text and a link to To review.
- **Closing a changed form.** It asks **Finish later** · **Delete** · **Keep editing**. An empty form closes silently. The Group's floating "Resume draft" goes; the item is in To review instead.
- **Offline.**
  - Finish later keeps the expense **on this phone**, saying "You're offline, so it stays on this phone. It shows in To review as 'On this phone'."
  - Account items stay read-only.
  - Nothing is ever uploaded automatically on reconnect (ADR 0008).
- **Moving a phone item into your account.**
  - Opening an "On this phone" item offers Save expense and Finish later. Finish later uploads it as a Draft prepared by the member, keeping the payload and operation identity until it's acknowledged.
  - Any uncertain earlier save of that expense is resolved first, so recovery can never create a second Expense.
  - Crash recovery keeps working and its items appear as "On this phone".
- **Carry-over.** Existing "Continue" and "Resume draft" entries from older app versions appear as "On this phone" after the update. Nothing is lost or uploaded.
- **"Prepared by" on Android.** Expense rows, Expense details and Activity show "prepared by Claude" from the field added in ticket 4.
- **Leaving a Group.** The Leave sheet adds: "You have 3 items in To review for <Group>. They're kept but hidden while you're not a member." This only appears when the count is above 0.

Design: the ReviewForm board (online, offline, closing with changes, To review full, after Finish later) and ReviewGroup's "prepared by ChatGPT" row.

## Acceptance criteria

- [ ] Finish later creates a member Draft online, keeps the item on the phone offline, and is disabled at the limit with the per-member text.
- [ ] The close prompt appears only for a changed form, and each choice does what it says. "Resume draft" is gone.
- [ ] Moving a phone item into the account is explicit only, keeps its identity until acknowledged, and resolves an uncertain earlier save first. A test proves there's no double Expense after a lost reply.
- [ ] Nothing uploads automatically on reconnect. A test proves it.
- [ ] Items from older app versions appear as "On this phone" after an update test.
- [ ] Expense rows, details and Activity show "prepared by <assistant>".
- [ ] The Leave sheet shows the item count when there is one.
- [ ] Render tests through the mobile controller cover every state at 130% text and in dark. The mobile HTTP verifier covers Finish later and moving an item into the account.

## Context for whoever picks this up

- **Parent spec:** #403. Read it first: its decisions are final.
- **Design:** the canvas https://claude.ai/artifact/R73Hkvu43SAkDqWDoKLMN9, page **"Phone: To review"**.

- **Words:**
  - **Draft** is the term in code and docs.
  - Members see **To review**, **Finish later**, **Delete** and **Check again**.
  - Never show "Draft", "revision", "request" or "collection" to members.
- **Flags.** Everything stays behind the existing persistent-drafts flags (server, web public and Android public). Production has them off; turn them on locally and in tests.
- **House rules:**
  - Pure shared logic lives in `@splitbook/shared`, with no framework, DB or DOM imports (ADR 0002).
  - Changes to existing reads are additive: Android and the mobile HTTP verifiers read them.
  - Money is exact minor units.
  - Fictional data only: the repo is public.
  - Unit tests must pass with `TZ` set to UTC, Pacific/Pago_Pago, Pacific/Kiritimati and Pacific/Tongatapu. Build date labels with the app's own formatter, never hard-coded.
  - Tables that scroll sideways need a focusable named region.
  - Light and dark, 130% text, and axe-clean.
- **PRs:**
  - Need the `full-ci` label.
  - Re-record pilot screenshot baselines only if they really change, in CI's Linux Playwright container, in their own commit.
  - Commit messages are plain, with no model names and no Co-Authored-By trailer.
  - Never delete branches.
