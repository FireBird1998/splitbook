## What to build

An item a Connected assistant prepares the way Claude did on staging should be Ready in To review, and Save N ready should save it. Claude's item had one payer with no amount for them, no Category, and everything else present.

- **One shared completion step.** The shared Draft validators gain one step that turns Draft values into Expense input. It applies exactly two rules:
  - a lone payer with no amount pays the whole Expense amount;
  - a missing Category becomes Other.
  - It never fills in anything else.
- **Everything that judges or saves an item uses that step:**
  - readiness and the named missing facts in the shared To review model;
  - the server's missing fields and problems;
  - the server's review, meaning the allocation and the duplicate check;
  - the Save N ready selection and its totals;
  - saving.
  - The server stops listing Category as a missing fact.
  - Stored Draft values aren't rewritten, so the review fingerprint doesn't change.
- **Rules that stay:**
  - With two or more payers, each needs an amount.
  - A lone payer whose amount differs from the total is a problem, in member words.
  - An item with no payer at all still needs "who paid" and keeps the "didn't know who paid" note.
  - An invalid Category is still refused.
- **The web review panel:**
  - An item with one payer and no amount opens in the one-payer mode, "Paid by …".
  - Changing the amount keeps that payer paying all of it.
  - With no Category stored, the Category control shows Other. Changing it stores the member's choice.
- **Android:** with no Category stored, the Category control shows Other. A lone payer already shows in the one-payer mode.
