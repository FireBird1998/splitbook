## What to build

Connected assistants should see the Category choices and know how to prepare items that end up Ready. They should also talk about To review, not drafts.

- **Category choices.**
  - The item tools that create and replace items take Category as the fixed set of Expense Categories, each with its label, instead of free text.
  - An unknown Category is still refused.
- **Group details.** The Group context tool returns the Category choices, with id and label, alongside members, Tags and currency. This is an additive change.
- **Guidance in the tool descriptions:**
  - "For one payer, give who paid; they paid the whole amount. For several payers, give each amount."
  - "Choose a Category only when the member's words make it clear; otherwise omit it, and it's saved as Other."
  - The existing rules stay: never invent payers, dates, participants or amounts.
- **Words.**
  - The descriptions refer to "items in the member's To review" and ask assistants not to call them drafts.
  - Tool names stay the same, so existing connections and clients keep working.

## Acceptance criteria

- [ ] The MCP connection suite (real OAuth and the official MCP SDK) checks that:
  - the listed item tools show the Category choices with their labels;
  - the Group context returns the Category choices;
  - creating an item with a valid Category stores it;
  - an unknown Category is refused with a clear message.
- [ ] The tool descriptions include the one-payer and Category guidance. They call the items "items in the member's To review" and ask assistants not to call them drafts.
- [ ] Read-only connections are unchanged:
  - the item tools stay hidden without the preparing permission;
  - the Group context still works.
- [ ] The existing connection suite tests pass.
