## What failed
The "PR checks" job fails at "Start this run's backend": `pnpm swarm up --mongo-port 27017 --server production`.
- The log says `Seeding … The seed failed (exit code 1)`, and `backend.log` ends with `DRAFT_TRANSACTIONS_REQUIRED`.
- **Cause:** `apps/mobile/scripts/dev-backend/seed-fixtures.mjs` now calls `expenseDraftService.create`. Draft writes require MongoDB transactions (ADR 0008), but that job's Mongo is a standalone `mongo:7` service on 27017. Your local run passed because you used a replica set.
- **The same problem would hit the verifier next.** `verify:shared-drafts` is now picked up by `verify:all`, which runs every `verify:*` script, and its Save N ready also needs transactions.

## What to change
1. **CI (`.github/workflows/ci.yml`, `pr-checks` job):** give swarm a single-node replica set.
   - Mirror what the `verify` job already does: a `docker run … mongo:7.0.39 mongod --replSet … --bind_ip_all` container, then `rs.initiate` with the host `127.0.0.1:<port>`.
   - Put it on its own port, and pass that port to both `pnpm swarm up` and `pnpm swarm down` with `--mongo-port`.
   - Leave the existing `mongo:7` service in place if anything else in the job uses 27017. If nothing does, remove it.
2. **Seed (`seed-fixtures.mjs`):** keep `seed.mjs` working on a standalone Mongo, because people's local dev backends may be standalone.
   - Add the fictional Claude Draft only when the server supports transactions. Otherwise skip it and print one plain line saying so.
   - Keep the fixture's identity and values as they are.
3. **Verifier (`verify-shared-drafts.ts`):** if the backend can't do transactions, fail straight away with a plain message: "This verifier needs a replica-set MongoDB, because saving Drafts uses transactions."
4. **Don't change anything else in the PR.**
