# T07 — Review and save one Draft on both clients

## What to build

Members review a Draft in SplitBook, resolve missing fields and duplicate warnings, and save exactly one Expense.

## Acceptance criteria

- [ ] Use complete Expense rules and existing ledger mutation behavior; no assistant save endpoint/tool is introduced.
- [ ] Warn about similar authorized Expenses and the owner’s other Drafts; never inspect or expose another member’s private Drafts.
- [ ] Require acknowledgment of current duplicate warnings bound to the reviewed revision; changed context requires review again.
- [ ] Convert atomically with a durable outcome mapping so retries, concurrent saves and lost replies return the same Expense.
- [ ] Enforce current membership and fresh review after leave/rejoin; concurrent save/discard has one coherent result.
- [ ] Success removes the Draft from active capacity and updates normal ledger views; invalid saves leave it available.
- [ ] Demonstrate the complete review/save journey on web and Android, including stale and unknown outcomes.
