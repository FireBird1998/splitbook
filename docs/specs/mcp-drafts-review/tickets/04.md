# T04 — Keep and revisit private Drafts on web

## What to build

A member explicitly keeps incomplete expenses as Drafts on web and finds them after reopening the Group.

## Acceptance criteria

- [ ] Provide a private online collection with one collection per owner per Group and no ledger or activity effects.
- [ ] Accept incomplete facts without invented defaults; show missing fields and preserve valid existing Expense entry behavior.
- [ ] Enforce at most 10 creations per request and 100 active Drafts per Group across all owners atomically, including absent members; no partial insertion on malformed or over-capacity creation.
- [ ] Show the agreed Group-limit message and ask the member to clear Drafts without exposing other owners or allowing them to delete others’ work.
- [ ] Use exact request identity so a retry returns the original entries and a changed payload conflicts; reject new access when membership is absent.
- [ ] Integrate Group and account deletion from the start, including replay metadata and deletion races; document transaction prerequisites and cleanup compatibility.
- [ ] Validate authenticated HTTP behavior with a real test database and a browser Keep as Draft/reopen journey. Evaluate existing prototype code before adopting it.

## Blocked by

None — can start immediately
