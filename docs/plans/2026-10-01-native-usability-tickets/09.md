# 09 Pilot TanStack Query for Activity reads

Status: draft awaiting ticket-breakdown review; proposed label `ready-for-agent`.

## What to build

Optionally migrate one complete Activity read flow to TanStack Query and measure whether it simplifies reads without weakening recovery or cleanup.

## Acceptance criteria

- [ ] Map Activity invalidation dependencies, transfer fetch/state/invalidation ownership together and remove the competing owner for that resource.
- [ ] Use network-only validated fetches and an explicit persistence adapter preserving original timestamps and scope; do not wrap fallback data as a fresh network success.
- [ ] Wire native online/focus listeners once; suppress duplicate controller triggers and distinguish paused/offline from loading.
- [ ] Keep authentication, drafts and all financial mutations outside the pilot; exclude mutations from persistence and automatic resume.
- [ ] Pass offline restart, account switch, denial, delayed response/persistence and request-count gates; publish a keep/revise/revert decision with measurements.
- [ ] This optional ticket does not gate the core usability release; full ledger-read migration requires a separate decision.
