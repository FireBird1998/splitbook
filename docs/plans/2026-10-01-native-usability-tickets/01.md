# 01 Required Expense fields and actionable corrections

Status: draft awaiting ticket-breakdown review; proposed label `ready-for-agent`.

## What to build

Complete the create/edit correction loop for Amount, Description, date and Tag, including clear required labels, inline errors, and first-error focus.

## Acceptance criteria

- [ ] Blank or whitespace-only Description identifies the field before any network request; no financial write occurs.
- [ ] Create and edit show the same human-readable errors without serialized validation details.
- [ ] Invalid, zero, negative or excess-precision Amount and impossible date have field-specific feedback; shared currency rules remain authoritative.
- [ ] Missing or unavailable Tag is identified without substituting another Tag; current availability is rechecked before saving.
- [ ] Submit exposes all relevant errors and moves to the first invalid input with the keyboard visible; corrections preserve unrelated entries.
- [ ] Rendered interactions and public-controller regressions verify field identity, correction, no write on invalid input, and draft preservation.
