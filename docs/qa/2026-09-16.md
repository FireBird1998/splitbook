# Splitbook QA — 16 September 2026

Assessed commit `35984f7` locally on macOS, Node 22.22.2, pnpm 10.23.0 and MongoDB 7. Browser journeys used the production build and Chromium; screenshot comparisons used the repository's Linux Playwright 1.62.1 image.

**Result: 482 automated tests passed, but exploratory QA confirmed four defects.** No application code was changed. These findings remain open.

## Confirmed findings

### QA-01 — P2: Saved currency preference is ignored for new groups

1. Enter as Alex and open Settings.
2. Choose USD under Preferred Currency and save. The UI displays “Settings saved!”
3. Open `/groups/new`.

Expected: USD is selected, consistent with the Settings helper text “Used as default when creating new groups.” Actual: INR is selected. A subsequent `GET /api/user/profile` returned HTTP 200 with `preferredCurrency: "USD"`, confirming persistence succeeded.

Cause: `apps/web/src/app/(main)/groups/new/page.tsx:38` initializes the currency to INR and does not load the profile preference. Initialize it from the saved preference, preserving an explicit user selection if loading finishes late.

Evidence: `apps/web/output/playwright/qa-2026-09-16/exploratory/page-2026-09-16T09-47-07-595Z.yml` and `page-2026-09-16T09-47-43-574Z.png`.

### QA-02 — P2: Profile save failures have no visible feedback

1. Open Settings, clear Name and click Save Changes.
2. Observe `PATCH /api/user/profile` return HTTP 422 with a name minimum-length validation error.

Expected: a visible field error or failure message. Actual: the save spinner stops with no error or explanation; the empty input remains.

Cause: `apps/web/src/app/(main)/settings/page.tsx:47` handles only `res.ok`. HTTP errors do not throw, so the catch block never handles validation/server responses. Parse and display non-success responses; validate the field before submission.

Evidence: `apps/web/output/playwright/qa-2026-09-16/exploratory/page-2026-09-16T09-44-50-355Z.yml` and `page-2026-09-16T09-45-20-733Z.png`.

### QA-03 — P2: Whitespace-only names are accepted and stored as empty

Authenticated request: `PATCH /api/user/profile` with JSON `{"name":"   "}`.

Expected: HTTP 422, leaving the existing name intact. Actual: HTTP 200 with `name: ""`; a subsequent GET confirmed the empty name was persisted. The profile was restored immediately after the probe.

Cause: `apps/web/src/app/api/user/profile/route.ts:14` checks minimum length before trimming. Trim before validating the minimum length. The update also does not enable Mongoose update validators.

Evidence: `apps/web/output/playwright/qa-2026-09-16/splitbook-qa-whitespace.log`.

### QA-04 — P2: Serious accessibility contrast violations escape the main test gate

The core browser report recorded serious `color-contrast` violations on persona entry, dashboard and most balance-screen variants, while all tests passed. The helper in `apps/web/playwright/fixtures.ts` fails only on critical violations.

A separate scan of the fully rendered light-theme Settings page reproduced:

| Element        | Foreground/background | Ratio  | Required |
| -------------- | --------------------- | ------ | -------- |
| Active session | `#1a9a6e` / `#ffffff` | 3.56:1 | 4.5:1    |
| Sign Out       | `#e04f3d` / `#ffffff` | 3.92:1 | 4.5:1    |

`apps/web/src/lib/theme/createAppTheme.ts:85` maps the positive/negative accent colors directly to success/error main colors. Use text-safe semantic colors for these small text elements and strengthen the application accessibility gate to include serious findings after addressing the existing failures. The component catalogue's stricter gate already passes.

Evidence: `apps/web/output/playwright/qa-2026-09-16/splitbook-qa-settings-axe.log`; the main browser HTML report contains the per-screen axe attachments. Dashboard node counts are affected by pre-existing local demo groups and should not be treated as a count of distinct defects.

- Run logs and exploratory snapshots/screenshots: `apps/web/output/playwright/qa-2026-09-16/` (gitignored).

- Pilot report: `apps/web/playwright-pilot/report/index.html`.

- Google redirects and identity outcomes were simulated using the repository's test verifier; real Google login, production cookies, Vercel and Atlas were not exercised.
- Mobile checks used Chromium emulation, not physical devices, Safari or Firefox.
- Pilot error scenarios use controlled API fixtures. Their passing results do not establish backend behavior for every failure condition.
- This was functional, access-control, responsive, visual and automated accessibility QA, not load testing, a penetration test or a complete manual screen-reader audit.
- Existing `.claude/` content was untouched. No issues were published and no product fixes were applied.
