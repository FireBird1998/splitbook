# Expo SDK 58 upgrade verification

Tested on 22 October 2026, from main `8faa788b83a1b16122c0e84636807c52cce2fcf5`.
The upgrade moves Expo 57 to 58.0.17, React Native 0.86.3 to 0.88.0, and React
19.2.3 to 19.3.0. It uses React Native's strict instance types rather than opting out.
Widgets are a separate change.

## Automated checks

- `pnpm install --frozen-lockfile --offline` passed after updating the lockfile.
- `pnpm mobile exec expo install --check`: dependencies are up to date.
- Expo Doctor: 20 of 20 checks passed.
- `pnpm swarm gate --mongo-port 27958 --vitest-workers 2`: all 18 steps passed,
  including lint, typecheck, formatting, ceilings and every mobile HTTP verifier.
- The gate passed 6,869 unit tests: shared 2,005, swarm 122, mobile 3,232, web 1,475,
  landing figures 35. Vitest used at most two workers.
- Fresh Android generation passed with the SQLite and status-bar config plugins.
- ARM64 `:app:assembleRelease` passed with SDK 58's default R8 optimization enabled.
- ARM64 `:app:assembleDebug` passed.

The gate and device backend used a dedicated throwaway MongoDB 7.0.39 replica set on
port 27958. The device backend served fictional fixtures on port 4298; Metro used 8088. Neither the shared backend nor a staging or production database was used.

to their original values, off and on respectively. The backend-unavailability check
used the reverse mapping because an emulator's loopback connection can remain reachable
when its radio settings change.

## Limits

These checks do not verify real Google sign-in, a production-signed APK, physical-device
behaviour, an SDK 57-to-58 installed-app update, or iOS. The release check above is a
startup and configuration-guard smoke; the functional journeys used the development
client with fictional accounts. Hosted CI results belong to the PR's checks.
