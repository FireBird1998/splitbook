## Method observations

- The rate table was seeded locally with fictional daily quotes marked with the Frankfurter source, including EUR→INR 92.1 and JPY→INR 0.56. The check exercised the real cache read, provenance, entry and Record paths; it did not call or validate an external quote provider.
- Airplane mode and removing the API reverse initially left a pre-existing adb-tunneled HTTP connection usable. That first attempt was not counted as an offline result. For the valid checks, Wi-Fi was also disabled and the existing proxy connection was closed; the API reverse remained removed. Metro’s reverse stayed available for the loaded development bundle. Afterward the API reverse, Wi-Fi and airplane-mode state were restored.
- Each reply-loss injection produced three dropped-response HTTP attempts before the app displayed uncertainty, then one successful explicit Retry. All four attempts retained the same body/key hashes and returned the same ledger identities; there was no additional Settlement. The trace does not by itself locate those immediate repeated attempts in JavaScript versus native networking.
- Fixture membership removal was deliberately seeded directly, as requested: the normal app refuses leaving with open Debts. The two former-member Expense allocations were seeded to Alex, so he was an endpoint of the refused offer; absence of an offer was not merely because the viewer was a third party.
