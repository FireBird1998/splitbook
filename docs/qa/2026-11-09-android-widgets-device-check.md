## Bugs found

### B01 — Standard release cannot run the required local demo QA configuration

**Tracking:** [#1013](https://github.com/FireBird1998/splitbook/issues/1013)

**Severity:** Blocks the required release QA pass; not evidence that a correctly configured production build is broken.

**Reproduce:** Set EXPO_PUBLIC_APP_ENV=development and both local API/auth URLs; assembleRelease; install and launch.

**Observed:** Build setup needed; no persona sign-in or Home. The runtime developmentConfig explicitly rejects non-development JS builds. This is a QA configuration blocker; no production-mode demo bypass was attempted.

**Screenshots:** `Release-build-setup-blocked-actual.png`.

**Resolution:** Release-mode widget checks run on a staging APK with widgets on and a staging account. The signed-in release destinations pass in [the staging release check](2026-11-09-android-widgets-release-staging-check.md). The development-config refusal stays.

### B02 — The first tap after force-stop wakes the widget but does not open the app

**Tracking:** [#1009](https://github.com/FireBird1998/splitbook/issues/1009)

**Severity:** Blocks the stated force-stop acceptance criterion; ordinary process-death routing passed in debug.

**Reproduce:** In the R8 widgets-on release, return to the launcher, am force-stop the package, then tap Balances once. Wait ten seconds and inspect the resumed activity. Tap again without force-stopping.

**Observed:** The first tap changes stopped=true to false and redraws the widget, but NexusLauncher remains the foreground activity after ten seconds. The second tap brings MainActivity to the foreground (then B01 prevents local demo sign-in). A warm tap also foregrounds MainActivity. Debug cold taps after ordinary process death do reach the requested destinations.

**Screenshots:** `Release-cold-tap-confirmed.png`, `Release-second-tap-opens.png`, `Release-warm-tap-Balances.png`.

`Release-cold-confirmed.json` records `beforeStopped=true`, `afterStopped=false`, and NexusLauncher still resumed after ten seconds. `Release-second-tap.json` records MainActivity resumed after the second tap. Clearing the package’s stopped flag alone was not counted as an app launch. Authenticated release destination routing remains blocked by B01.

### B03 — Live Group widget avatars have one initial instead of two

**Tracking:** [#1011](https://github.com/FireBird1998/splitbook/issues/1011)

**Fix:** #1011 adds first name and two initials to the widget copy, reusing the app's initials function. New reads distinguish members sharing a first name; older copies keep their one-letter fallback. Follow-up device evidence covers both sizes and Hide amounts.

**Severity:** Does not block turning the switch on; track as a follow-up.

**Reproduce:** Sign in as Alex; read Goa Friends Trip Balances; place a Group widget; view 4x2 or 4x3.

**Observed:** The avatars show P and S rather than PS and SC. At this check, the widget copy stored first names only, so the two-initial renderer had no surname. Synthetic board fixtures in earlier passes carried full names.

**Screenshots:** `WidgetGroup4x3-dark-actual.png`, `WidgetGroup4x2-actual.png`.

### B04 — Font-size changes do not redraw widgets after process death

**Tracking:** [#1012](https://github.com/FireBird1998/splitbook/issues/1012)

**Severity:** Does not block turning the switch on; track as a follow-up.

**Reproduce:** Background the app, kill its process without force-stop, change font_scale from 1.0 to 2.0, and inspect the placed widget.

**Observed:** The status bar uses 200% text, but widget bitmaps and their filenames remain unchanged at 100% until a later app/widget redraw. This reproduces the W8 limitation.

**Screenshots:** `Font-before-process-death.png`, `Font-after-process-death-200.png`.

### B05 — Archiving is presented as lost access instead of the final archived balance

**Tracking:** [#1008](https://github.com/FireBird1998/splitbook/issues/1008)

**Severity:** Blocks turning the widgets switch on.

**Reproduce:** As Sam, configure Group and Quick for the QA archive Group and read its Balances. As Alex, archive it with DELETE /api/groups/:id. Tap the Group widget again.

**Observed:** The server still returns the archived Group and its Balances to Sam (HTTP 200; membership retained). The app deletes its widget part, adds its id to lostGroupIds, and both widgets say Sam is no longer in the Group. No Archived tag or final balance appears. The transport treats an archived Group read as GROUP_ARCHIVED denial before the widget can retain the final state.

**Screenshots:** `WidgetStateArchived-Group-actual.png`, `WidgetStateArchived-Group-dark-actual.png`, `WidgetStateArchived-Quick-actual.png`, `WidgetStateArchived-Quick-dark-actual.png`.

`Archived-membership-proof.json` records `isArchived=true`, Sam still a member, HTTP 200 for both Group and Balances, and Sam’s INR balance of −12. `Archive-before.json` has the Group part; `Archive-after.json` has no part and includes its id in `lostGroupIds`. The expected archived board could not be reached through the real app read path.

### B06 — Setup records remain after the flag-off upgrade removes the widgets

**Tracking:** [#1010](https://github.com/FireBird1998/splitbook/issues/1010)

**Severity:** Does not block turning the switch on; track as a follow-up.

**Reproduce:** Place all three kinds; upgrade to the widgets-off release; compare Android’s active widgets with the widget_setup table.

**Observed:** AppWidgetService has no Splitbook providers/widgets, but widget_setup still contains records for removed IDs 19, 20 and 21. This violates #987’s removal rule. The records contain account/Group identifiers and choices; no old widget remains on the launcher.

**Screenshots:** `Flag-off-upgrade-main.png`, `Flag-off-upgrade-Group-page.png`.

The screenshots show Android’s removal. `Flag-off-provider-state.json` has no remaining provider lines; `Flag-off-after.json` still has setup ids 19, 20 and 21. This is the setup-deletion rule from #987, separate from the successful visible removal/disabled-picker check.
