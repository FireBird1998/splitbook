# Web and Android share Tag management safety rules

Web and Android manage the same Group-scoped Tags through shared backend rules: only admins may change them, at least one active Tag must remain, stale edits must fail without overwriting newer changes, and every interrupted Tag action must remain explicitly recoverable without duplicate effects or overwriting subsequent changes. This covers create, rename, archive, restore and the existing web deletion of unused Tags; Android adds no Delete action and exposes management only through Group options. Names remain unique within a Group ignoring case, and restoring an Archived Tag reuses its identity and history.

A UI-only Android addition would inherit the current backend’s stale-form overwrite and ambiguous retry gaps, while leaving web controls able to bypass the new safeguards. We therefore accept the additional shared API and web-client work instead of implementing different rules in each client. Recovery identifies the submitted action independently of the Tag’s current name or state. A read-only check cannot make an unapplied change; only an explicit retry may submit the original action, subject to current permissions and stale-edit protection. The owner confirmed the consolidated design and local implementation on 13 October 2026.

Existing saved Expenses and recurring/Draft references keep their identities when a Tag is renamed or archived. Archiving requires explanation and confirmation; no automatic substitution changes another member’s unfinished Draft. Historical Groups already lacking an active Tag stay readable and can be repaired by explicitly creating or restoring one, without automatic backfill.
